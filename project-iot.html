01OVERVIEW

Monitoring that
doesn't stop.

The system continuously monitors temperature, humidity, smoke/gas levels and motion using multiple sensors connected to an ESP32. Based on these readings, the system can automatically control a fan and lamp.

Unlike a cloud-dependent monitoring system, the project is designed to continue functioning when internet connectivity is unavailable. Sensor readings and actuator states are stored locally in SPIFFS and synchronized with ThingSpeak when connectivity is restored.

02SYSTEM

Sense.
Decide.
Respond.

01

SENSING

DHT11 measures temperature and humidity, MQ2 monitors smoke and gas levels, and PIR detects motion.

02

PROCESSING

The ESP32 reads sensor values and applies local decision-making logic for automated control.

03

ACTUATION

A relay-controlled fan provides ventilation while a lamp responds to motion detection.

04

CONNECTIVITY

Sensor and actuator data is sent to ThingSpeak during normal online operation.

03OFFLINE MODE

When the internet
goes down.

Connectivity failure does not stop the system. When Wi-Fi becomes unavailable, the ESP32 switches to local operation and begins storing timestamped sensor readings and device states in its internal SPIFFS flash memory.

01Wi-Fi connected
02Send data to ThingSpeak
03Wi-Fi unavailable
04Store data in SPIFFS
05Reconnect & synchronize

Stored records are written to /data.csv using the format timestamp, temperature, humidity, gas, motion, fan and lamp. When connectivity returns, the ESP32 reads the stored records and uploads them to ThingSpeak before clearing the local file.

04AUTOMATION

Decisions happen
on-device.

01

TEMPERATURE

If temperature exceeds 30°C, the fan is turned ON.

02

GAS / SMOKE

If MQ2 rises above the defined threshold, the fan is activated for ventilation.

03

MOTION

Motion detected by the PIR sensor switches the lamp ON.

04

NO MOTION

When motion is no longer detected, the lamp switches OFF.

08OUTCOME

Local resilience.
Cloud convenience.

The project demonstrates that a single low-cost ESP32 platform can combine sensing, decision-making, actuation, cloud communication, local storage and user interaction in one integrated system.

Its offline-first architecture allows the system to maintain monitoring and control functionality during internet outages, while automatically restoring cloud synchronization when connectivity returns.
